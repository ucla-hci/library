# Key Points

---

### Key attributes of prototypes

> • *Prototyping* is an *approach* based on an evolutionary view of software development, affecting the development process as a whole
• *Prototyping* involves producing *early* working versions (”prototypes”) of the future application system and experimenting with them
• *Prototyping* provides a *communication basis* for discussions among all groups involved in the development process, especially between users and developers.
> 

Overall, prototyping “enables us to adopt an approach to software construction based on *experiment* and *experience”.*

### Dimension #1: kinds of prototypes

- **Presentation prototype**: “supports the initiation of a software project …
    - “to convince the clients that the future application system is either feasible or that its user interface and handling is in line with user requirements …
    - “to show the user’s view of the envisaged system, i.e., it will present important aspects of the user interface …
    - “if the technical solution of a problem is unclear, … may present functional details to convince the customer of the possibility of solving this problem.”
- **Prototype proper**: “a provisional operational software system that is constructed parallel to the information system model …
    - “to illustrate specific aspects of the user interface or part of the functionality and helps to clarify the problem at hand”
- **Breadboard: “**to help clarify construction-related questions facing the development team**”**
- **Pilot system**: “actually used in the application area itself as the core of the application system
    - “ceases to be any strict distinction between the prototype and the application system.”

### Dimension #2: goals of prototypes

- **Exploratory prototyping**: “used where the problem at hand is unclear. Initial ideas are used as a basis for clarifying user and management requirements with respect to the future system”
- **Experimental prototyping**: “focuses on the technical implementation of a development goal”
- **Evolutionary prototyping**: “not merely used as a tool in the context of a single development project; it is a continuous process for adapting an application system to rapidly changing organizational constraints.”

### Dimension #3: relationship between prototypes and application systems

- **Specification:** “A prototype is part of the application system specification … not used as a building block in the application system itself; it is a ‘throw-away’”
- **Early version**:  “Prototypes are enhanced to produce the application system”
- **Experiment**: “Prototypes serve to clarify problems only … for the purposes of acquiring knowledge, with no intention of building an application system”

### Horizontal vs. vertical prototyping

Horizontal prototyping

- builds a wide range of features with minimal implementation
- focuses on exploring UI/UX design
- is useful for early stages

Vertical prototyping

- implements a small set of features with complete functionality
- focuses on technical feasibility and risks
- is useful for critical or high-risk features

### Prototyping incurs overhead

> … the importance of breadboards in developing creative solutions and design options. … to experiment and “play around” with breadboards produced concepts and design ideas which, though frequently not incorporated into the current system version, nevertheless formed or might form the basis for subsequent revisions.
