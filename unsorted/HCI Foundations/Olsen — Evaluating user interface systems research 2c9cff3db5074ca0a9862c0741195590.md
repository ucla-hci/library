# One Sentence


This paper argues the importance of innovating user interface system infrastructure and toolkits, point out how traditional usability evaluation falls short in evaluating such research, and propose claims that can be made and how to support them.

# Key Points


### The type of research this paper focuses on

> ... the creation of new architectures for interactive systems ...
> 

### The three assumptions of usability evaluation

> The first is "walk up and use." This assumes that all potential users have minimal training ... "walk up and use" assumption does not work well for problem domains that require substantial specialized expertise, such as user interface programming or design.
> 

> The second is the standardized task assumption ... A task that is suitable for a usability experiment must have low inherent variability so that any variance can be assigned to the differing techniques being tested [rather than] to variations in approach to the task or user expertise.
> 

> The third assumption is scale of the problem. The economics of usability testing are such that it must be possible to complete any test in 1-2 hours.
> 

> Usability testing is attractive because it can produce a statistically valid, clearly explained, easily compared result. However, toolkit and UI architecture work rarely meets any of the three assumptions of usability testing.
> 

### How comparing new and old toolkits introduces confounding factors

> Any comparison between a new toolkit and an existing toolkit will be confounded by familiarity with the existing toolkit and the need for expertise in using the new one.
> 

### What is the fatal flaw fallacy

The practice of overwriting the entire work because of a single flaw.

> The farther such a team reaches into new territory the more compromises will be required and the more supporting ideas must be left unresolved.
> 

### Overview of the proposed UI systems evaluation

- Set the system in **situations, tasks and users**;
- Argue for the **importance** of enabling the specific user group to be able to conduct specific tasks in specific situations;
- Showing how the system can solve **problem not previously solvable**;
- Showing how the system can afford a set of general-enough tasks;
- Show how the system can **reduce solution viscosity** (making the task process less frictional) by means of;
    - Flexibility;
    - Expressive leverage;
    - Expressive match.
- Showing how the system can empower new design participants;
- Showing how components of the system can be combine to yield greater power;
- Showing scalability;

### The STU way of thinking about evaluating UI infrastructure

> Every new piece of interactive technology addresses a particular set of users, performing some set of tasks, in some set of situations. It is critical that interactive innovation be clearly set in a context of situations, tasks and users.
>

### How to claim/evaluate system's empowering new participants

1. Show why certain participants must be involved in the UI creation process;
2. Show why existing tools are not acceptable for this population;
3. Show how new tools are more accessible, easer or more effective for this population;

### Ways of combining components of a UI toolkit

- Inductive combination, e.g., grammars, UI component trees.
    - Need to show that "the set of primitives is either relatively small or can be easily extended";
    - Need to show the coverage as well as what's not covered;
- Simplifying interconnection, e.g., makes it easier to connect two disparate components;

### On the scalability of UI toolkits

> Any new UI system must either show that it can scale up to the size of realistic problems or that such scaling is irrelevant because there is an important class of smaller problems that the new system addresses.
> 

# Other Notes


### A well-established infrastructure impedes new developments

> Systems based on one screen, one keyboard and one mouse are the new equivalent of command-line interfaces.
> 

### Why working on UI systems architecture? What values are added?

1. Reduce development viscosity (less friction in the process);
2. Least resistance to good solutions;
3. Lower skill barriers
4. Power in common infrastructure
5. Enabling scale

### Design process and choices

> The dominant cost of any design processes is the making, expression and evaluation of choices
>
